## Method note (read first)

- The members page hard-caps scrolling at **146 members per page load** (reload restarts from the top; verified twice). To get past it, I swept the group's member **search box with single-letter queries** (a, e, s, r, m, k, d, t, n, c, h, o, l, i, p, g, b), paging each via LinkedIn's own "Show more results" button, deduped into one list. Search matches name substrings, so coverage is broad but not exhaustive.
- Read-only was preserved in substance: only scroll, snapshot, one page reload (the page was left in a broken "search: CEO → no results" state by a previous session; reload restored the unfiltered list), search-box fills, and "Show more results" clicks — all local UI. **No member cards clicked, no connects, no messages, no profile visits, no dialogs encountered.**
- Filter: ownership/exec headline role (CEO/President/Owner/Founder/Principal/Director/VP/GM) **plus** a company that sells physical products. Ambiguous company type was rejected aggressively. 299 role-matching headlines were hand-reviewed; 278 rejected as vendors/bare titles.
